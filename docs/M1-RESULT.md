# Milestone 1 の結果

対象は `semantic-browser-fixture`（査読ジャーナル、HAL + ALPS）。
実装者はそのソースを読まず、HTTP と実行時取得の ALPS だけで書いた。

## 検証項目に対する答え

| `docs/PLAN.md` の問い | 答え |
| --- | --- |
| HAL と ALPS だけから、事前知識なしに遷移候補を発見できるか | **できる** |
| 一連の処理で自律的に巡回できるか | **できる** |
| Laya が意味情報に基づいて妥当な次の一手を選択できるか | **部分的にしかできない** |

3 番目が Milestone 1 の核心であり、否定的な答えが出た。これは PoC が
仮説を棄却したのであって、実装の失敗ではない。

## 意味で選べる範囲

7 ホップを要するゴールを 1 段ずつ与えた結果（`laya-multilingual-mlx`、
ゴール文にはデータにも記述にも現れない語を使用）。

**5/7 が正解。** 記述が届いていれば、語彙が一致しなくても含意を追える。
`argued against publishing` から `the person who wrote an assessment` へは
辿れた。

## 通しで走らせると 1 歩目で落ちる

```
step 0  /                 goReviewerPool 0.65   ← 誤り
step 1  /reviewers        reviewer_0     0.84
step 2  /reviewers/rv-01  候補なし、終了
```

`goReviewerPool` の ALPS 記述にはこう書いてある。

> 査読を依頼できる人の名簿を開く。**特定の原稿の査読者を探す用途には使えない。**

明示的な否定を読まずに選んでいる。段ごとに正しい state を与えれば 5/7 でも、
1 段外すと以降の文脈が崩れ、通しでは到達しない。

## 測定された限界

| | 証拠 |
| --- | --- |
| **否定を読まない** | 「〜には使えない」と書かれた候補を 0.82、「まだ掲載されていない」を 0.79 で選択。両チェックポイント共通 |
| **役割を混同する** | 「referee の名前」に対し `goAuthorProfile` を 0.96 |
| **記述のない候補は解けない** | `_embedded` の rel に descriptor がない場所。`review` に descriptor を足すと 0.23 → 0.40 で正解に入れ替わった |
| **確信度は正しさと対応しない** | 誤答 0.96、正答 0.29。Clarity 検査の指標には使えない |
| **記述の言語がモデルを決める** | 英語チェックポイントは非 ASCII を落とす。日本語 ALPS では title しか届かず 3/7 |

Laya は決定的である（同一入力 5 回で完全一致）。上のばらつきはモデルの
揺らぎではなく、入力の差による。

## ALPS の書き方への含意

- **肯定形で書く。** 「これには使えない」は効かない
- **コレクションの項目にも descriptor を与える。** ないと意味の経路が存在しない
- **記述の言語とチェックポイントを合わせる**

## この結果の限界

- fixture は 1 つ。ドメインを変えれば数字は動く
- ゴールは 1 つ。言い回しを変えると成績が変わることは測定済み
- 到達したかどうかの判定は人手。自動化していない
